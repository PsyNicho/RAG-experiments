# Conclusion

1. **Successful retrieval**: Generally the model was able to return the correct chunks from the index in response to queries. Despite some variations in the way the questions were asked the model was able to return relevant information. Showing that semantic search can find relevant information even if there are no exact keyword matches.
2. **Vocabulary and phrasing matter:** The way questions were worded affected the similarity score. For example when the question “What is SQL?” was asked, the similarity score for the SQL chunk was high (0.72). Whereas for the question ‘how can I get the users older than 18’ the similarity score was low (0.2979).
3. **Related concepts can cause retrieval errors**: Sometimes the model would return the wrong chunks based on the question. For example for the question ‘which search is more efficient for finding elements in sorted data?’ the model returned linear search as the best option over binary search. Also for the question ‘which data structure deletes the most recent item first?’ the model returned queue over stack.
4. **Similar chunks can have close scores:** Chunks that are similar can have high similarity scores. For the question ‘what is a hash collision?’ both hash collisions and hash functions had high similarity scores. This suggests that if the concepts overlap then it can be difficult to distinguish between the different chunks.
5. **Similarity scores do not guarantee correctness:** Having a high similarity score doesn’t necessarily mean the chunk answers the question correctly. The order needs to be considered with respect to what the result should be.
6. **The index cannot recognize missing information:** The index doesn’t understand when information is missing. When asked a question about gradient descent the index returned irrelevant chunks. This is because the index always returns the most similar available results. There is no determination of whether the result is relevant enough to answer the question.
7. **Overall finding**: Overall the current VectorIndex is a good base for semantic searching. However the results depend on how the question is worded and how similar the related chunks are. This will help to inform any future improvements to our RAG system.
